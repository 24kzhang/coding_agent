# 网页交互验收

对用户要求的交互执行真实浏览器检查。优先使用本轮已发现的浏览器工具；没有浏览器工具时，使用项目声明的 Playwright 测试依赖和配套浏览器运行时。

## 环境

- Python 项目通过 `uv add --dev playwright` 声明依赖，再从同一项目环境运行 `uv run python -m playwright install chromium`；不能仅安装 Python 包却遗漏浏览器。
- Node 项目通过自身包管理器声明 Playwright 依赖并安装配套浏览器。不能借用宿主全局包。
- 使用 Playwright 管理的独立无头浏览器，不复用用户日常浏览器资料目录，不猜测系统 Chrome 路径或临时加入禁用安全功能的参数。
- 安装目录及下载缓存沿用执行器提供的环境。启动失败应读取完整诊断，解决运行权限或依赖，不能修改业务断言来掩盖环境问题。

## 有限脚本

执行器等待命令结束。验收脚本应使用 `subprocess.Popen` 启动本地服务，轮询就绪，再操作浏览器；在 `finally` 中关闭浏览器、终止并等待服务。使用真实解释器、工作目录和项目配置，不另开一个会阻塞的服务命令。

## 检查方法

1. 打开页面，等待应用的就绪状态，读取可见 DOM 后确定控件。
2. 按需求实际点击、输入、选择和按键，断言操作后的结果、URL 或控件状态。不能用源码匹配、页面文字存在或 `--dump-dom` 代替交互。
3. 资源来源应检查元素实际 `src`、CSS 资源 URL 及浏览器请求；普通文本中出现路径不代表该路径被加载。
4. 流式交互应观察中间状态与完成状态，核对后续输入的历史保留和隔离；捕获载荷应在调用时深复制。
5. 检查加载、空态、错误和中断反馈；只在需求要求的范围内增加场景，不扩展产品功能。
6. 必需检查不得通过 `skip`、空脚本或返回零绕过；明确区分已执行、失败与尚未执行。用中文输出可核验的检查项与结论，必要时保存截图。

参考：Playwright 官方文档 https://playwright.dev/python/docs/intro 和官方 MCP https://github.com/microsoft/playwright-mcp 。
